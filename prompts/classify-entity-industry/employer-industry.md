# 给一个公司实体判「行业 + 商业模式」

**业务场景**:talent-graph 已注册一批标准公司实体(阿里巴巴、招商银行、菜鸟…)。
要按"在什么行业干过""在什么类型的公司干过"检索/分析人才,就得给每个公司实体标好
两件事——**它属于哪个行业**(银行/电商/医疗…),以及**它是不是平台型公司**。挂进
`tag_entity_map` 后,下游 SQL 才能 JOIN 出"这段经历属于电商 / 属于平台公司"。
行业和模式都不是业内公认闭集,所以这是**逐实体分类**,不是清单枚举——**严禁用 `/define-tag`**。

**任务**:拿到一个标准公司实体,判**两条轴**,各自逐个挂载
(`tag link --tag <code> --entity <uuid> --match-mode exact`):
1. **行业轴**:它属于哪个(或哪几个)行业桶。
2. **模式轴**:它是不是"平台"。
一次任务处理一个实体;批量由调度方拆成多个并发任务各跑一个。

## 判的是「这个实体本身」

- 看 `entities.description` 里的主营;不清楚就 WebSearch 核这家公司**主要做什么**。
- 判的是**这个实体本身**,不是它母公司——子母公司各自独立判(`match_mode=exact`):
  菜鸟判物流、蚂蚁判金融,不因为同属阿里就都套同一个标签。集团总部按总部自身主营判。

## 行业轴:它在哪个领域干活

- **挑它实际经营的领域**:招商银行→银行,中国国航→交通运输,海风教育→教育。
- **平台型公司,行业轴挂它所服务的那个领域**,不要因为"它是个 App / 是个平台"就
  另立门户:滴滴服务出行→交通运输,拼多多做实物电商→电商,蚂蚁做金融→金融,
  冬日中医服务医疗→医疗。是不是平台,交给模式轴去标。
- **有几类业务现实世界没有对口行业,它们本身就是数字原生领域**,直接挂数字桶:
  实物线上零售→电商,游戏研发/发行→游戏,通用软件/SaaS/云/工具/搜索/AI→软件IT,
  社交/社区/IM→社交。(注意反例:短视频/影视/直播内容→传媒;出行→交通;
  外卖到店→消费;金融科技→金融;在线教育→教育;互联网医疗→医疗——这些有对口
  现实行业,别因为"在线"就往数字桶塞。)
- **所服务垂直没有对口桶**(农业、会展)但确实在卖软件 → 落软件IT(久农云=农批 SaaS);
  既无对口桶、也不是在卖数字产品 → 行业轴可以空着(只标模式或两轴都不标)。

## 一个实体可以挂多个行业桶

检索要的是 recall——找"保险人才"和"银行人才"时,平安都该命中。所以:

- 实体有**实质业务 + 实质用工**的行业,**全挂**(平安→银行+保险+资管;腾讯→社交+游戏)。
- 但只挂"实质",**沾边不挂**:一家电商公司有个小支付牌照,不挂金融。
- 多元控股集团(中信/复星/光大)→ 挂其所有有实质主营的桶;纯财务持股、自身不经营
  实业的投资平台 → 按主导业务判,判不出就不挂。

## 模式轴:它是不是「平台」

- **平台** = 撮合 / 连接供需两方,自己**不下场**生产、进货、承运、服务——它提供的是
  那个让别人来交易 / 匹配的"场子"。拼多多(撮合买卖家)、滴滴(撮合乘客与司机)、
  美团(撮合商家与食客)、Boss直聘(撮合企业与求职者)→ 挂平台。
- **自营 / 实体不挂**:自己下场做的——京东自营进货卖货、国航自己飞、海风自己组织
  教学、捷威自己造电池——**不挂平台**(模式轴默认就是自营,不另设"自营"标签)。
- 一家公司可以既自营又做平台(京东自营 + 开放第三方平台)→ 挂平台(它确有平台业务)。

## 行业桶清单(行业轴,facet=industry)

**金融**
- `ind_banking` 银行 —— 商业银行/政策性银行
- `ind_securities` 证券/投行 —— 券商(含投行条线)、纯投行
- `ind_insurance` 保险 —— 寿险/财险/再保险/保险经纪
- `ind_asset_mgmt` 基金/资管 —— 公募/私募/券商银行资管/信托(二级市场)
- `ind_pe_vc` 创投/PE —— 一级市场股权投资

**专业服务**
- `ind_consulting` 咨询 —— 战略/管理/IT/人力咨询
- `ind_accounting` 会计/审计 —— 四大及内资所
- `ind_law` 律所 —— 律所及法律服务

**数字原生**(现实世界无对口行业的数字业务本体)
- `ind_ecommerce` 电商 —— 实物商品线上零售/电商(平台型另在模式轴挂平台)
- `ind_gaming` 游戏 —— 游戏研发/发行/电竞
- `ind_software` 软件/IT —— 通用软件/SaaS/云/开发工具/搜索/AI/IT 服务(卖数字产品本身)
- `ind_social` 社交/社区 —— 社交/即时通讯/UGC 社区

**工业/医疗**
- `ind_automotive` 车企 —— 整车制造(零部件归制造)
- `ind_manufacturing` 制造 —— 工业装备/电子/半导体/汽车零部件
- `ind_healthcare` 医药/医疗 —— 制药/生物科技/器械/CRO/医疗服务(含互联网医疗,平台型另挂平台)

**基础设施/民生**
- `ind_real_estate` 房地产 —— 开发/物业/商业地产(施工归建筑)
- `ind_energy` 能源/电力 —— 油气/电力/煤炭/新能源运营(设备制造归制造)
- `ind_telecom` 电信运营 —— 三大运营商及通信网络服务(设备硬件归制造,软件归软件IT)
- `ind_construction` 建筑/工程 —— 施工/基建/工程设计(地产开发归房地产)
- `ind_consumer` 消费/零售 —— 快消/线下零售/餐饮/本地生活/消费品牌(实物电商归电商)
- `ind_media` 传媒/文娱 —— 传媒/广告/影视/内容/文旅(游戏归游戏)

**交通/物流**
- `ind_transportation` 交通运输 —— 航空/铁路/公路城际/公交/城市轨交等客运及出行(**客运**;货运归物流)
- `ind_logistics` 物流 —— 快递/货运/仓储/供应链(**货运**;客运归交通运输)

**公共服务**
- `ind_government` 政府/公共 —— 党政机关/事业单位
- `ind_education` 教育/科研 —— 高校/科研院所/培训(含在线教育)

## 模式轴标记(facet=business_model)

- `mdl_platform` 平台 —— 撮合 / 连接供需两方、自己不下场自营。仅在判定为平台时挂;
  自营 / 实体不挂(无"自营"标签)。

## 没有专属桶的几类,这样归

库里这几类常见、但不单设桶,按主体性质散进上面已有的桶(散不进、查不清就行业轴不挂):

- **军工/国防科研院所**(CETC 各所、兵器研究所等)→ 作为科研机构归 `ind_education`;军工**制造厂**(造装备/武器整机)→ `ind_manufacturing`。
- **部队/军队单位** → `ind_government`;**军队医院** → `ind_healthcare`。
- **农业/农垦**(种植/养殖/粮油上游、兵团团场)→ 没有对口桶,行业轴**不挂**(若是卖农业软件/农批平台,按数字原生归 `ind_software` + 平台)。

## 命中就挂,不命中就不挂

- **两条轴各自判、各自挂**:行业轴挂命中的桶(可多个),模式轴是平台才挂平台。
- 行业轴一个桶都不实质命中、或主营查不清 → 行业轴不挂;不是平台 → 模式轴不挂。
  不挂不是数据丢失,是 list 标签的正向语义:下游 JOIN 自然不出该标签,如实。
- 防过严:**只要在某桶有实质业务就挂**,别因为"它还做别的/不够纯"而漏挂——
  把握不在"纯不纯",在"这块业务是否实质"。
- **行业判定落在"看得出具体做什么"上,不在笼统标签上**:描述只有"商贸 / 贸易 / 实业 /
  控股 / 科技 / 服务"等不指向具体经营内容的泛称、又无品类或产品线索、web 也查不到这家
  公司究竟做什么 → 等同主营查不清,行业轴不挂(别把"商贸"顺手归消费、"科技"顺手归软件IT)。
  反过来,描述里有具体品类 / 产品 / 服务对象就照常判,哪怕名字带"商贸 / 科技"——
  卡的是泛称无实据,不是这些词本身。
- 别凭公司名臆测:"XX 汽车销售"是经销零售(归消费),不是车企;拿不准某桶算不算,
  宁可不挂那个桶,也不硬塞进去。

# 解析一条 company raw_name 的 entity 归属

对一条原始公司名,先判断它在 talent-graph 里应该用哪种**建模动作**表达,再写入归属记录。不要只问"它归谁",而要判断:它是已有主体的写法、一个应保留的下级业务、一个应自成根的雇主主体,还是需要跳过的脏数据。

## 锁定 company 域

raw 来自员工的任职单位。每条 raw 都按 company 处理:即使看起来像学校 / 医院 / 政府机关 / 工作室,也表示员工在该单位任职,不要改判成 school 或其它 entity_type。建 entity 和挂 alias 全程使用 company。

## 图谱服务什么问题

company 实体图服务人才分析,不是工商股权图。`parent_id` 只回答一个下游问题:给母体打 subtree 标签时,这家员工该不该算进母体这一系。

因此:

- entity 粒度按雇主品牌 / 业务主体 / 可分析人群来定,不是按法人全称来定。
- parent 表达稳定的业务从属和雇主系归属,不是每一层股权持有。
- 建 entity 用业务上常用的品牌名或主体名,不用 raw 里的法律全称。
- 不要把"大众认知"理解成知名度投票。它要和员工语境、业务边界、以及下游 subtree 标签是否应覆盖这批人一起判断。

## 先选建模动作

### 1. alias 到已有 entity

raw 只是某个已存主体的另一种写法,就挂 alias 到该 entity。

常见情况:

- 法人全称 / 地区公司 / 英文名 / 简称 / 历史名称
- 母公司的用工法人或注册壳,员工岗位画像和母体无从区分
- 持有 / 投资平台的名字就是某品牌名加「控股 / 集团 / 投资」等壳词(联想控股之于联想)，大众认知不把它和品牌区分开 → 当品牌的写法 alias 到品牌 entity，不单独建顶层、更不要反过来让它当品牌的 parent
- raw 所属业务已经被当前 entity 的 canonical 和 description 覆盖,没有必要单独成点

例:北京百度网讯科技有限公司是百度的法律主体写法,不是一个需要单独分析的子业务；「联想控股」则是「联想」的控股壳写法，同样 alias 到联想、不建成联想之上的顶层。

### 2. 建下级 entity,并挂 parent

raw 指向一片可单独分析的业务或雇主品牌,但大众和业务语境里仍属于某母体这一系,就新建下级 entity,并把这个下级 entity 的 `parent` 设为母体。alias 挂到新建的下级 entity,不要直接挂到母体。

判断信号:

- 有自己的业务边界或雇主品牌
- 有一片员工可以被单独分析
- 未来可能需要给这个业务单独打 exact 标签
- 同时,母体的 subtree 标签也应该覆盖这批员工

例:菜鸟 / 淘天是阿里系下的独立业务,应建下级 entity 挂阿里;金山云 / 金山办公(WPS)应建下级 entity 挂金山。业务臂跨到不同行业也照挂:君联资本 / 弘毅投资(投资)、佳沃(农业)虽与「联想」主业不同、大众仍认作联想系，应建下级挂联想、不各自成孤儿根。独立上市、独立法人都不是自成孤儿根的理由。

要把下级 entity 挂到母体时,先 `entity search` 母体是否在库里。母体已存在就复用;不存在时,按 skill 流程自上而下建出必要层级。同一集团多家下级业务挂同一母体,不要各自留成孤儿根。

### 3. 建顶层 entity,不挂 parent

raw 本身就是一个可作为分析顶层的雇主主体,或它上面的持有方不代表实际雇主系,就建顶层 entity。

常见情况:

- 自身是大众和员工都会直接识别的雇主主体,不是某个母体的一条业务线
- 母公司已退出持股或实控已易主
- 上层只是财务投资方、国资平台、控股平台,不是实际经营这门生意的雇主系
- 被收购后大众和员工仍认原品牌,认知没有转移到收购方

例:海航在大众认知中仍是海航,不因方大收购航空业务就挂到方大;京东方不沿股权链追到北京电子控股。

蚂蚁、猎豹这类自身就是强雇主主体的公司,即使历史上来自更大集团,也应自成顶层;但猎户星空这类明确属于猎豹体系的下级业务,应建下级 entity 挂猎豹。注意区分:名字只是「品牌 + 控股 / 集团」的持股壳(联想控股之于联想)不算这里的「强雇主主体」，按第 1 类 alias 到品牌、别建成品牌之上的顶层。

### 4. keep / 跳过

证据接不上时不要硬挂。名字像、缩写像、description 像,都只能触发核实,不能直接证明同一家或父子关系。

如果当前已有归属且没有证据证明它错,保持现状。如果 raw 查不到可靠资料或各来源冲突,按 skill 流程挂「（无法识别）」;如果只是占位词或匿名写法,挂「（无效输入）」。

## 被收购不等于归入收购方

遇到收购 / 易主 / 剥离,不要把"被 X 收购"直接读成"挂 X"。先问两件事:

1. 收购方是否把这门生意当自己的业务持续经营?
2. 大众和员工是否已经把这家认作收购方这一系?

两者都成立,才挂收购方或挂到收购方体系下。只成立股权事实不够。

- 品牌被吸收、员工和市场都已改认收购方体系 → 挂收购方体系。
- 卖方退出、业务清算、或员工与大众仍认原品牌 → 留原品牌。
- 收购方只是财务 / 控股 / 综合集团平台,即使持股或接盘,也不要机械上挂。

同一品牌的不同板块,如果大众和员工只认作同一个品牌,不要按历史运营方拆开。

## 证据顺序

优先看:

1. raw 背后真实员工的岗位画像和业务内容
2. 现有 entity 的 canonical / description / aliases / children
3. 公开资料中的业务边界、品牌关系、并购和拆分事实
4. 股权和法人关系

低权重信号:

- 名字相似
- 只有一个同名网页结果
- 单纯法人不同
- 单纯独立上市 / 独立法人

这些只能作为线索,不能单独决定动作。

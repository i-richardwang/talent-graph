# 解析一条 company raw_name 的 entity 归属

对一条原始公司名,判定它在 talent-graph 里应当归属哪个 entity,并写入归属记录。

## 锁定 company 域

raw 来自员工的任职单位——每条都是某人在此任职的用工主体。确定性地按 company 建:raw 看起来是学校 / 医院 / 政府机关 / 工作室,也照样当作雇主 company 处理(员工在该单位任职),不因它"不像公司"就改判成 school 等其它 entity_type、或漂到别的域。整条判决里 entity_type 钉死为 company,建 entity 和挂 alias 全程用它。

entity 层级反映业务从属,不反映股权持有。建 entity 用品牌名,不用法律全称。

**建 parent**:raw 在市场上被认知为某集团旗下的子业务/子品牌——品牌身份和集团绑定,不是独立公司。
**不建 parent**:raw 自己是有独立市场认知的公司——即使有控股股东。沿股权链追出控股方当 parent 是错的。

## 子业务臂挂母体,顶流巨型集团自成主体

判"挂母体"还是"自成主体",看的是**这家是不是大众认知里叫得出名字的顶级主体**,不是它有没有独立上市 / 独立法人(那是股权治理维度、不当判据)。

- **子业务臂**(自己不是大众叫得出的顶级主体、大众认知就是"X 系的")→ 挂回集团母体,即便独立上市:金山云 / 金山办公(WPS)挂「金山」、菜鸟 / 淘天挂「阿里」。要挂母体时**先 search 母体在不在库**——在就直接挂,不在就先建母体再挂(两层建法见紫光集团 / 紫光展锐);**同集团多家挂同一母体、别各自成根**,否则本是"同集团细化"的会在下游被误判成"挂错集团"。
- **顶流巨型多业务线集团**(大众张口就叫得出、本身下辖众多自己的子业务)→ 它就是顶、自成主体,即便出身某集团也**不上挂**:蚂蚁(支付宝 / 网商银行 / 蚂蚁国际 / 芝麻信用…)自成主体、**不挂阿里**;2023 剥离是股权事件、不当判据。这跟顶部"不建 parent:有独立市场认知的公司"是同一条——门槛是"顶流主体",不是"叫得出名字"。
- 母公司已退出持股 / 实控已易主 / 母公司是纯财务或国资持股平台(京东方之于北京电子控股,不追)的,也自成根、不沿股权链上追。

## 被收购 ≠ 归入收购方:看大众认知 + 谁在经营,不看"收购"这个动作

raw 的东家发生过收购 / 易主时,别把"被 X 收购"直接读成"挂 X"。判据是**大众与员工现在把这家认作谁、谁在实际经营这门生意**,不是收购这个动作本身:

- 收购方**接手并持续当自家业务经营、且大众认知随之改口到收购方** → 挂收购方(EMC 并进 Dell EMC、品牌溶掉 → 挂 Dell)。**注意"持续经营"是时效判断、要看现在**:家乐福中国 2019 被苏宁收购运营时应挂苏宁,但 2025 苏宁失去品牌许可、业务清盘后又该脱钩独立——挂载随经营状态变,别套用旧结论。
- 卖方**退出式出售 / 业务清算、收购方没当自家生意持续经营、大众与员工仍认原品牌** → **留原品牌,不挂收购方**。雅虎中国 2005 被阿里收购,但那是 Yahoo 退出中国、业务随后关停,员工自我认知与大众认知都是"在雅虎工作" —— 挂「雅虎」,不算阿里系。
- **关键是大众认知有没有真转移到收购方,不只是"谁在经营"**。收购方若是大众陌生的财务 / 控股 / 综合集团平台,即便它在经营这门生意,大众与员工仍认原品牌、不会改口 → 留原品牌。海南航空被方大收购、方大也在经营航空业务,但大众认知里它还是"海航"、没人把海航员工算作"方大系" → **海航自成主体,不挂方大**(这套图谱是按大众认知的雇主主体给员工归类、做数据分析,不是梳理股权;方大只是控股财务方)。

强外资品牌被本土方收购后关停 / 边缘化的,几乎都属后者:认知锚在原品牌,别因"被谁收购过"就改挂。同一品牌收购前后、不同板块(如雅虎中国消费业务 vs 雅虎研发中心)大众只认作同一个"雅虎"的,归并为一个实体,不按运营方拆。

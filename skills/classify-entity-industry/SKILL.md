给定**一个公司实体**,判它属于哪些雇主行业,把命中的行业桶逐个挂到这个实体上。挂上之后,下游按工作经历 JOIN 就能筛出"这段经历属于哪个行业"。

行业不是业内公认闭集(没有"所有银行"的权威名单),所以这是**逐实体分类**——判这一个实体本身属哪行,不是去枚举某个行业的成员清单。

**全自动执行**:不与人交互。判得准就挂,查不清就不挂——**不挂是正常结果,不是失败**。

任务: $ARGUMENTS

---

## 在管的行业桶

在管行业桶 = `facet=industry` 的那批 list 标签;`tag list --facet industry` 列出每个桶的 `tag_code` 与口径。本次任务的归类判据(各桶边界、一个实体能不能多挂、什么算"实质业务")随任务给定。

## 判断起点

实体的 canonical 名 + description 说明它主营什么,是判断的起点;不足以判清主营时用搜索工具核这家公司**主要做什么**。业务随时间变(并购 / 改名 / 转型),即使常识也搜核实,不要凭训练记忆判。

判的是**这个实体自身**,不是它母公司——子母实体各判各的。

## 挂载

命中的桶逐个挂:

```bash
talent-graph tag link --tag <ind_code> --entity <entity_id> \
  --match-mode exact --reasoning "<判决依据>"
```

`--match-mode exact` 让归属只作用于这个实体本身、不沿父子链覆盖后代(菜鸟挂物流,不连带把阿里其它子公司拖进物流)。命中几个桶就 link 几次,重复 link 幂等。

## 查不清 / 不命中

主营查不清、或判不进任何在管桶 → **不挂**。这是 list 标签的正向语义:不挂 = 这家不属于任何在管行业,下游 JOIN 自然不出行业标签,如实。不要为了"挂点什么"硬塞。

## 失败处理

搜索工具不可用 / 失败 / 限流 → 终止任务,报错退出。**不要**当"查无源"跳过——会导致零写入但表面成功。
